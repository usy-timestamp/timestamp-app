# 타임 스탬프 구조 설명

개발을 모르는 사람이 읽고 남에게 설명할 수 있게 썼다. 부분마다 비유를 한 줄씩 붙였다.
지금은 M2(1차 화면 7개)까지 끝난 상태다.

## 한 문장

운전 중 이상한 소리가 나면 한마디로 그 순간을 표시하고, 차가 그 앞뒤 30초의 속도, 브레이크, 기어를 남겨 두었다가, 정차 후 정비사가 읽을 리포트로 만들어 준다.

## 차 신호를 읽는 두 갈래

앱은 차의 값을 두 군데에서 읽는다.

| 갈래 | 읽는 값 | 비유 |
|---|---|---|
| AAOS 표준 API (`CarPropertyManager`) | 속도, 기어, 외기온 | 어느 차에나 있는 공용 계기판을 읽는 것 |
| Pleos Vehicle SDK | 브레이크, 경고등 | 현대차가 따로 열어 준 창구에서 받는 것 |

**속도와 기어를 AAOS 표준 API로 읽는 이유**: Pleos 문서가 그렇게 하라고 권한다. 근거는 아래 두 문서다.
- https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/pleos-connect-sdk-api
- https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/app-runtime-environment-resources-guide/app-retrieve-cluster-info

**차종마다 다를 수 있어서**: 값을 읽기 전에 그 차가 그 값을 주는지 먼저 물어본다(`getCarPropertyConfig`, `checkXxxCapabilities`). 안 준다고 하면 그 값은 화면과 리포트에 "수집 불가"로 표시하고 앱은 계속 동작한다. 식당에서 주문 전에 "이 메뉴 되나요?"를 먼저 묻는 것과 같다.

## 확인된 것 (M0)

자세한 표는 `docs/SIGNALS.md`.
- 기어, 속도, 브레이크, 외기온, 경고등, 위치가 모두 에뮬레이터에서 앱으로 들어온다
- 브레이크는 "밟음 또는 안 밟음"만 온다. 몇 퍼센트 밟았는지는 오지 않는다
- 음성 출력과 음성 인식(기기 내 모드, 한국어)이 P단과 D단 모두에서 된다
- 주행 중에는 시스템이 일반 앱 화면을 덮는다. 주행 중 화면은 "주행 중 사용 가능" 선언을 한 화면만 보인다. 화면이 덮여도 앱은 뒤에서 계속 돌아간다

| `voice/VoiceTrigger` | 음성 인식. 계속 듣다가 받아 적은 글에 "타임스탬프"가 있으면 표시로 넘긴다. 한 번 받아 적으면 1초 쉬고 다시 듣는다 | 귀 |
| `voice/TimestampCommand` | 받아 적은 글이 기록 명령인지 판정하는 한 줄 규칙 | 암호 확인 |
| `probe/ProbeActivity.kt` | 신호와 음성을 하나씩 불러 보고 결과를 화면과 로그에 적는 확인용 화면. 디버그 빌드에만 들어간다(`app/src/debug`). 제출용 빌드에는 없다. 제품 화면이 아니다 | 공사 전에 수도와 전기가 들어오는지 틀어 보는 것 |

## 기록 한 건이 만들어지는 순서

1. 서비스가 켜지면 1초마다 차 상태(속도, 브레이크, 기어, 경고등, 외기온)를 버퍼에 넣는다
2. 운전자가 "타임 스탬프 찍어줘"라고 말한다. 음성 인식이 글로 받아 적고, 규칙이 명령인지 확인한다
3. 그 순간을 0초로 잡고, 버퍼에서 25초 전까지의 값을 꺼내 둔다
4. 5초를 더 기다리며 값을 모은다
5. 25초 전부터 5초 후까지 31칸으로 정리해 데이터베이스에 저장한다. 못 읽은 칸은 비워 둔다(수집 불가)
6. "기록했어요"라고 말한다

시연과 시험을 위해 같은 기록을 디버그 명령으로도 만들 수 있다(디버그 빌드에서만).

## 확인된 것 (M1, 에뮬레이터)

- D단, 시속 38km, 브레이크를 밟은 상태에서 기록을 요청하자 31칸이 저장됐고, 직전 5초의 속도와 브레이크 밟은 초 수가 맞게 들어갔다
- 시험 음성 "타임 스탬프 찍어줘"를 인식기에 넣자 음성 트리거로 기록이 저장됐다
- 저장 뒤 "기록했어요" 음성 요청이 나갔다
- 앱을 껐다 켜도 기록이 남아 있다
- 단위 테스트 15개 통과 (링버퍼 5, 기록 흐름 8, 명령 판정 2)
- 사람이 직접 말한 소리로 기록되는지는 아직 확인하지 못했다

## 재현 조건을 만드는 규칙

1. 같은 부위로 표시된 기록이 2건 이상이면 한 묶음으로 본다
2. 각 기록에서 말하기 직전 5초의 값만 본다 (소리는 말하기 조금 전에 났기 때문)
3. 속도는 그 5초의 최솟값과 최댓값을 모아 전체 범위로 쓴다
4. 브레이크는 "N번 중 M번 밟는 중"으로 센다. 과반이 밟았으면 문장에 "브레이크를 밟을 때"를 넣는다
5. 기어는 가장 많이 나온 값을 쓴다
6. 못 읽은 항목은 문장에서 빼고 "수집 불가로 빠졌어요"라고 따로 알린다

## 확인된 것 (M2, 에뮬레이터)

- 처음부터 끝까지 실제 흐름: 첫 실행, D단 주행, 브레이크를 밟은 채 음성으로 3번 기록(시속 42, 36, 31km), P단, 기록마다 앞 왼쪽 바퀴 표시, 리포트에 "시속 31에서 42km로 달리다 브레이크를 밟을 때, 3번 중 3번 밟는 중"과 블랙박스 확인 시각 3개 표시
- 정비소에 보여주기 화면, 수리 완료 저장 뒤 목록의 상태와 건수 변경
- D단으로 바꾸면 주행 중 화면만 보이고, P단으로 돌아오면 기록 목록으로 돌아옴
- 단위 테스트 37개 통과
- 음성은 시험 음성 파일로 넣었다. 사람이 직접 말한 소리로는 아직 확인하지 못했다

## 만들 예정 (M4)

```
recheck/   수리 후 같은 조건이 오면 먼저 묻기                    비유: "지난번 거기 아직 아프세요?" 하고 묻는 간호사
ui/        07 수리 후 확인 이력, 08 설정, 시운전 알림
```

## 음성으로 표시하는 방법 (설계 방향)

1. 1순위는 Pleos SpeechToText SDK다. 듣기를 시작하면 말이 들릴 때까지 기다렸다가 받아 적어 준다. 받아 적은 글에 "타임 스탬프"가 있으면 기록한다.
2. Gleo("글레오, 타임 스탬프 찍어줘")는 앱 스키마 승인을 신청할 수 없어 쓰지 않는다. 플랫폼이 열리면 붙일 향후 계획으로 둔다.
3. 시연 안정성을 위해 디버그 명령으로도 같은 기록을 만들 수 있게 한다.

## 정한 원칙

- 공개된 SDK 문서 범위에서만 만든다. 문서에 없는 기능은 향후 계획으로 돌린다
- 기록은 기기 안에만 둔다. 위치는 모으지 않는다
- 분석은 규칙으로만 한다. 머신러닝을 쓰지 않는다
- 차량 제어는 하지 않는다

## 주행 중에는 화면을 차지하지 않는다 (2026-11-12 변경)
- 기어가 P에서 벗어나면 앱이 자기 창을 닫는다. 내비처럼 앞서 보던 화면이 그대로 보인다
- 기록 서비스는 창과 따로 돌아서, 창이 닫혀도 "타임 스탬프 찍어줘"를 듣고 기록한다. 에뮬레이터에서 내비 화면인 채로 3건 기록되는 것을 확인했다
- 창을 뒤로 보내는 요청(moveTaskToBack)은 이 차량 화면에서 통하지 않아 창을 닫는 방식을 쓴다
- 달리는 중에 운전자가 앱을 직접 열면 버튼 없는 안내 화면(09)만 보여 준다
- 비유: 녹음기는 주머니 속에서 계속 돌고, 수첩은 차를 세웠을 때만 꺼내 본다

## 2026-11-12 저녁 변경 요약
### 화면
- 색은 짙은 남색 바탕에 라임 한 가지 강조. 번지는 빛, 반투명, 그림자를 쓰지 않는다 (Pleos 디자인 지침: 색은 적게, 장식 금지)
- 앱 창은 가로(1682 x 1210)와 세로(840 x 1210 안팎) 둘 다 맞춘다. 세로로 길면 한 줄로 쌓고 아래쪽에 탭 바를 둔다. 배율은 가로일 때 `너비 / 1280`, 세로일 때 `너비 / 640` (`ui/theme/Scale.kt`)
- 창 크기가 바뀌어도 보던 화면과 고른 값이 유지된다
- 누르는 곳은 76 이상, 누르면 95%로 줄어드는 효과
- 비유: 같은 내용을 넓은 책상에서는 양쪽으로 펼치고, 좁은 책상에서는 위아래로 쌓는다

### 운전자 메모 두 방식 (설정에서 고른다)
- 기록 후 되묻기(기본값): 명령만 말하면 기록을 저장한 뒤 "기록했어요. 어떤 소리였나요?"라고 묻고, 다음 말 한 번을 그 기록의 메모로 저장한다
- 한 번에 말하기: "스탬프, 끼익 소리가 나"처럼 말하면 명령어를 뗀 나머지를 메모로 저장한다. 음성 인식이 말을 둘로 끊어 주는 경우가 있어, 4초 안에 이어진 말을 메모로 붙인다
- 판단 로직은 Android와 무관한 순수 Kotlin(`voice/DriverMemoFlow.kt`, `voice/CommandMemo.kt`)에 있고 단위 테스트가 있다
- 비유: 되묻기는 접수 창구 직원이 "어디가 불편하세요?"라고 한 번 물어보는 것, 한 번에 말하기는 접수증에 증상까지 한 줄로 적어 내는 것

### 뺀 것
- 위치: 앱이 위치를 읽거나 저장하지 않으므로 권한과 안내 문구를 모두 뺐다
- 승인받지 않은 차량 권한(CAR_SAFETY, PRIVATE_CAR_SAFETY)과 신호 확인 화면은 디버그 빌드에만 남겼다

### 개인정보 안내
- 첫 실행 화면에서 모으는 것, 쓰는 곳, 보관 방법을 보여 주고 동의를 체크해야 시작된다. 설정 화면에서 다시 볼 수 있고 "모든 기록 지우기"가 있다
