# 시연 순서 (에뮬레이터)

준비물: 실행 중인 Pleos Connect 에뮬레이터, 브라우저로 연 Virtual Console(http://127.0.0.1:8088), 설치된 앱. 준비 방법은 `docs/SETUP.md`.
에뮬레이터는 화면 녹화를 하려면 창이 보이게 켠다 (`-no-window` 없이).

## 0. 시작 전
1. Virtual Console에서 기어 P, 속도 0, 브레이크 0
2. 앱 아이콘 "타임 스탬프"를 눌러 연다
3. 처음이면 01 화면에서 권한 2개를 허용하고 개인정보 안내에 동의한 뒤 "시작하기"
4. 기록이 남아 있으면 지우고 시작한다 (설정 화면이 생기기 전에는 앱 데이터 지우기)

## 1. 주행 중 기록 (세 번)
| 순서 | Virtual Console | 말하기 | 확인 |
|---|---|---|---|
| 1 | 기어 D | | 앱 화면이 스스로 내려가고 내비 화면이 보인다. 기록 준비는 뒤에서 계속된다 |
| 2 | 속도 50 | | |
| 3 | 20초쯤 달린 뒤 브레이크 60%, 속도 42 | | |
| 4 | | "타임 스탬프 찍어줘" | 5초 뒤 "기록했어요" |
| 5 | 브레이크 0, 속도 44로 20초, 다시 브레이크 60%, 속도 36 | "타임 스탬프 찍어줘" | "기록했어요" |
| 6 | 같은 방법으로 속도 31 | "타임 스탬프 찍어줘" | "기록했어요" |

- 받아 주는 말은 여섯 가지다: 스탬프, 스탬프 찍어, 스탬프 찍어줘, 타임 스탬프, 타임 스탬프 찍어, 타임 스탬프 찍어줘. 말 속에 "스탬프"가 들어 있으면 기록한다
- 기록은 말한 뒤 5초를 더 모으고 저장한다. 다음 기록은 "기록했어요"를 들은 뒤에 말한다
- 앞 25초가 차야 그래프가 꽉 찬다. 기록 사이에 20초 이상 달린다
- 마이크가 안 될 때 (디버그 빌드): `adb -s emulator-5564 shell am broadcast --user 10 -a io.timestamp.app.DEBUG_VOICE_FILE --es name utt1.wav`

## 2. 정차 후 확인
1. Virtual Console에서 브레이크 0, 속도 0, 기어 P. 아래 줄의 "타임 스탬프" 아이콘을 눌러 앱을 다시 연다. 기록 목록이 보인다
2. 맨 위 기록을 누른다. 차 그림에서 앞 왼쪽 바퀴를 누르고 "부위 저장"
3. 나머지 두 기록도 같은 부위로 저장한다
4. 목록 오른쪽에 "앱이 찾은 반복 증상" 카드가 생긴다. "리포트 보기"
5. 리포트에서 재현 조건 문장("시속 31에서 42km로 달리다 브레이크를 밟을 때")과 블랙박스 확인 시각을 보여 준다
6. "정비소에 보여주기"를 눌러 큰 글씨 화면을 보여 주고 "닫기"
7. "수리 완료 표시"를 눌러 날짜를 확인하고 "수리 완료". 목록에서 상태가 "수리 완료"로 바뀐 것을 보여 준다

## 3. 말로 설명할 것
- 차 그림과 그래프는 말한 순간의 앞 25초와 뒤 5초다
- 주황 띠는 브레이크를 밟은 구간이다 (차는 밟았는지 여부만 알려 준다)
- 블랙박스 확인 시각은 말하기 5초 전부터 말한 순간까지다. 블랙박스 기기와 연결하지는 않는다
- 기록은 이 차 안에만 저장된다

## 시연 전 점검
- 에뮬레이터 스피커 소리와 마이크 입력이 되는지 먼저 확인한다
- 기어를 D로 바꾸면 앱 화면이 내려가는 것이 정상이다. 달리는 중에 앱을 직접 열면 "기록은 정차 후 확인할 수 있어요" 안내 화면만 보인다
- 막히면 디버그 명령 `DEBUG_CAPTURE`로 같은 기록을 만들 수 있다 (`docs/SETUP.md`)

## 2026-11-12 저녁에 바뀐 시연 순서 (위 내용보다 이것이 최신)
1. 처음 실행하면 권한 2개(마이크, 차량 속도와 기어)를 허용하고, 개인정보 안내 아래 "위 내용을 확인했고 동의합니다"를 체크한 뒤 "시작하기"
2. 기어 D. 앱 화면이 내려가고 내비가 보인다
3. 저속 브레이크 상황을 세 번 만든다. 예: 속도 24로 20초쯤 달리다 브레이크를 밟고 속도 18, 그때 "스탬프"
4. 앱이 "기록했어요. 어떤 소리였나요?"라고 물으면 "끼익 소리가 나"처럼 답한다. "메모했어요"가 나온 뒤 다음으로 넘어간다
5. 같은 방법으로 속도 22에서 14, 속도 20에서 12
6. 속도 0, 브레이크 0, 기어 P. 앱을 다시 연다
7. 기록 세 개에 각각 들어가 차 그림의 왼쪽 앞바퀴를 누르고 "부위 저장"
8. "리포트 보기". 조건 문장 "시속 12~18km에서 브레이크를 밟을 때"와 운전자 메모를 보여 준다
9. "정비소에 보여주기"

- 숫자는 에뮬레이터에 넣은 값에서 나온다. 실제 차에서 잰 값이 아니므로 발표와 영상에서 "에뮬레이터 시연 시나리오"라고 밝힌다
- 메모 방식을 "한 번에 말하기"로 바꾸려면 설정 메뉴에서 고른다
- 에뮬레이터 음성 인식이 가끔 오류를 낸다. 명령이 안 먹으면 몇 초 뒤 다시 말한다

## Gleo 브로드캐스트 시험

최초 실행에서 개인정보 동의를 완료한다. Gleo 설치 여부와 관계없이 앱 수신 경로를 시험할 수 있다. 사용자 10인 에뮬레이터에서는 --user 10을 넣는다. ACTION_PARAM의 바깥 따옴표가 셸에서 제거되지 않도록 아래처럼 전달한다.

```sh
adb shell am broadcast -a RECORD_VEHICLE_MOMENT -p io.timestamp.app --es ACTION_PARAM '{"symptom":"끼익 소리"}'
adb shell 'am broadcast --user 10 -a RECORD_VEHICLE_MOMENT -p io.timestamp.app --es ACTION_PARAM '\''{"symptom":"끼익 소리"}'\'''
adb shell am broadcast --user 10 -a RECORD_VEHICLE_MOMENT -p io.timestamp.app
```

첫 요청은 증상을 메모로 저장하며 앱 질문을 생략한다. 마지막 요청은 증상 없이 기록하므로 설정에 따라 앱이 질문한다. 5초 뒤 저장 결과를 확인한다. 응답은 ai.pleos.playground.intent.action.APP_ACTION_RESPONSE 액션에 packageName과 response 문자열로 전달된다. response에는 functionName, status, message, mode, JSON 배열 문자열 data가 포함된다. 새 서비스의 과거 25초는 수집 불가이며, 백그라운드 FGS 시작이 막히면 fail이다. 거짓 성공을 반환하지 않는다.

순서 있는 adb 브로드캐스트의 result data에도 같은 응답 JSON을 돌려주므로, Gleo가 없어도 success 또는 fail과 이유를 명령 결과에서 확인할 수 있다.
